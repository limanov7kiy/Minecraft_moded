# Где поднимать сервер

Два сценария: сервер на ПК друга (бесплатно, но работает, только пока ПК включён)
или платный хостинг (24/7).

## Сколько ресурсов нужно нашей сборке (замер)
Замер `spark` на тестовом сервере (≈150 модов, 2026-10-10): после запуска и прогрузки участка 400×400 блоков
без игроков — **3,0 ГБ кучи + 0,6 ГБ вне кучи**, TPS 19–20, тик 4–5 мс (95% — 7 мс). Каждый игрок, который
исследует мир, добавляет ориентировочно 0,5–1 ГБ, Create/Valkyrien Skies/Mekanism-базы — ещё больше.

**Правило по ОЗУ (замер Потока 67): сервер занимает ≈ `Xmx` + 2,5 ГБ памяти** (куча + память вне кучи). `-Xmx10G`–`12G` → тариф
**16 ГБ**; на 12 ГБ при `-Xmx10G` запас почти нулевой.

Для **5–8 игроков**: `-Xmx10G` (в серверном пакете так и стоит, `user_jvm_args.txt`), машине — **12 ГБ свободной
памяти** под сервер (на ПК, где одновременно играют, — 24–32 ГБ всего), процессор с высокой однопоточной
частотой (Ryzen 5000/7000, Intel 12-го поколения и новее), SSD. Если TPS падает ниже 18 — `spark profiler`
покажет, какой мод тормозит.

- **Правила хостинга про моды / изменённые jar** — на страницах не найдены; юридически сборка остаётся нашим делом (см. «Назначение и лицензии» в `CLAUDE.md`), репозиторий и jar не публиковать.

### Чек-лист проверки на бесплатном тарифе Millida (решение владельца: сначала проверка, платный не оплачивать)
Регистрация и сервер 2 ГБ без карты; проверяем и записываем результат сюда (ДА/НЕТ + скриншот или цитата поддержки):
1. Выбор ядра: есть ли Forge **1.20.1 / 47.4.26**; выбор **Java 17**; можно ли править `user_jvm_args.txt` / стартовую команду (флаги `-Xmx`).
2. **SFTP**: адрес, порт, логин; заливка своего jar (`*-mmport.jar`) и папок `kubejs/`, `config/`, `defaultconfigs/`, датапаков; лимит размера и числа файлов; можно ли залить весь `*-server.zip` (1,5 ГБ) и распаковать.
3. **UDP 24454**: есть ли в панели «Сеть/Порты/Allocation»; если нет — запрос в поддержку на доп. UDP-порт (цена?) и проверка `port=-1`; проверка снаружи (клиент с Simple Voice Chat, `Voice chat server started at port …` в логе).
4. Консоль и команды (`/spark`, `/op`), перезапуск по расписанию, бэкапы (сколько, как восстановить), смена тарифа 12 → 16 ГБ без потери мира.
5. Условия: **возврат денег**, правила про загрузку изменённых jar/свои сборки (ToS), политика по CPU (overselling), реальный CPU (`/spark tps`, `cat /proc/cpuinfo`, если есть консоль).
Ограничение бесплатного тарифа — 2 ГБ: нашу сборку целиком (`-Xmx10G`) на нём не запустить, проверяются **панель, порт, SFTP, версия Forge/Java и условия**; нагрузочная проверка TPS — уже на платном тарифе (месяц).
Для голоса на 2 ГБ достаточно лёгкого теста (Forge + Simple Voice Chat): в логе `Voice chat server started at port …`, клиент подключается, в окне по **V** нет значка «нет соединения».
Если порт платный — узнать цену до оплаты. Дополнительно проверить смену тарифа 12 → 16 ГБ с сохранением мира (переход платный тариф ← бесплатный делается кнопкой в панели, мир и адрес сохраняются).
Итог проверки → владельцу: «берём платный 16 ГБ / другой вариант» (если не прошло — понадобятся ответы на бюджет и на то, кто админит VPS).

### Ответ поддержки Millida (2026-10-26)
**Это ответ ИИ-ассистента поддержки, не оператора** — перед оплатой подтвердить на бесплатном тарифе и/или у живой поддержки.
- **Память и JVM:** панель сама ставит `-Xmx`/`-Xms` = память тарифа + G1. «Параметры запуска» редактируются: свои флаги и `-D` можно (в т.ч. `-Dfml.queryResult=confirm`).
- **UDP для голоса:** дополнительный UDP-порт выдаётся в «Адрес и сеть», номер **автоматический — 24454 выбрать нельзя**. На игровой порт UDP **не проходит**
  (`port=-1` не годится) → в `config/voicechat/voicechat-server.properties` ставим `port=<выданный>`.
- **Forge 47.4.26:** «Настройки → Ядро и версия»; файлы по SFTP; серверный архив распаковывать в корне, **свои скрипты запуска (`start.sh`/`start.bat`) удалить**.
- **Диск:** лимита inode нет; 200 ГБ (тариф 12 ГБ) / 260 ГБ (16 ГБ).
- **Бэкапы:** автокопия раз в сутки (если играли), ручные хранятся 30 дней, восстановление кнопкой.
- **Смена тарифа:** повышение — сразу и без потерь; **понижение невозможно**. Пробного периода и промокодов нет (кроме бесплатного тарифа 2 ГБ).
- **Открытый вопрос:** лимит памяти контейнера — только куча (`Xmx`) или с запасом под память вне кучи (по нашему замеру `Xmx` + 2,5 ГБ)? Если лимит равен `Xmx`, сервер убьёт OOM-killer — проверить на платном тарифе сразу (`-Xmx` ниже памяти тарифа на 2,5 ГБ).

## Вариант A: ПК друга

Сначала проверить, есть ли у друга «белый» (публичный) IP: сравнить IP в настройках роутера
(WAN) с тем, что показывает 2ip.ru. Совпадают — IP белый.

| Способ | Что ставить игрокам | Плюсы | Минусы |
|---|---|---|---|
| **Проброс порта 25565** (если IP белый) | ничего | минимальный пинг, без посредников | нужен доступ к роутеру; IP может меняться (решается DDNS) |
| **playit.gg** | ничего | работает за NAT/CGNAT, постоянный адрес, бесплатный тариф | трафик идёт через их сервер — пинг выше; на бесплатном тарифе ближайший регион может быть далеко |
| **Tailscale / ZeroTier** (виртуальная LAN) | клиент VPN у каждого | обычно прямое P2P-соединение — пинг ниже, чем у туннеля; закрыт от посторонних | каждый игрок ставит программу и входит в сеть |
| **Radmin VPN** | клиент у каждого | просто, популярен в СНГ | только Windows, иногда нестабилен |
| **e4mc** (мод) | ничего | «открыть для сети» прямо из одиночного мира | хост должен сам сидеть в игре; адрес временный — для долгой сборки не подходит |

**Рекомендация:** если IP белый — проброс порта. Если нет — **playit.gg** для простоты
(друзьям ничего ставить не нужно); если пинг через playit окажется плохим — **Tailscale**.

Требования к ПК друга для модовой сборки: 6–8 ГБ RAM под сервер (средняя сборка на 50–150 модов),
процессор с хорошей однопоточной производительностью, SSD, проводное подключение.

## Голосовой чат: UDP-порт 24454

Simple Voice Chat ходит **отдельным UDP-портом 24454** (не через порт игры 25565, который TCP).
Если игра подключается, а в голосовом чате значок «нет соединения» (перечёркнутый динамик/наушники) —
не открыт именно этот порт. Настройки сервера: `pack/config/voicechat/voicechat-server.properties`
(`port` — какой порт слушать, `voice_host` — какой адрес сообщить клиентам; пусто = тот же, что у игры).

| Способ подключения | Что сделать для голоса |
|---|---|
| **Проброс портов** (белый IP) | в роутере, кроме `25565/TCP`, пробросить **`24454/UDP`** на тот же ПК; в брандмауэре Windows разрешить входящий UDP 24454 для Java (или правилом на порт). `voice_host` не трогать. |
| **playit.gg** | Добавить в агенте **второй туннель типа UDP** на локальный `127.0.0.1:24454` (первый — Minecraft Java, TCP 25565). playit выдаст адрес вида `xxx.ply.gg:12345` или `147.185.221.x:12345` — вписать его в `voice_host=xxx.ply.gg:12345` и перезапустить сервер. Клиенты ничего не настраивают: адрес приходит от сервера. Бесплатный тариф позволяет несколько туннелей, UDP в том числе. |
| **Tailscale / ZeroTier / Radmin VPN** | Ничего: в виртуальной сети все порты, включая UDP, доступны напрямую. Друзья подключаются к адресу хоста в сети (`100.x.y.z` у Tailscale), голос идёт туда же. Брандмауэр Windows всё равно должен пропускать Java (обычно спрашивает при первом запуске — разрешить для частных сетей). |
| **e4mc** | Голос не работает: e4mc туннелирует только TCP игры. |
| **Платный хостинг** | В панели хостинга выделить дополнительный порт (часто называется «Additional port»/«Allocation») и вписать его в `port=` (и в `voice_host=адрес:порт`, если хостинг за NAT). Если хостинг даёт только один порт — `port=-1` (голос по UDP на том же номере, что игра) и обязательно `enable-query=false` в `server.properties`: query тоже слушает UDP на этом порту, и SVC предупреждает о падении сервера. Узнать у поддержки, проходит ли UDP. |

Загрузка звуков AudioPlayer через браузер (`/audioplayer web`) по умолчанию выключена — ей нужен ещё один
TCP-порт (8080). Включить: `run_web_server=true` в `config/audioplayer/audioplayer-server.properties`, порт и
внешний адрес — в `config/audioplayer/webserver.properties`; открыть порт так же, как 25565. Без неё звуки
загружаются по ссылке (`/audioplayer url`) — портов не нужно.

Проверка: зайти на сервер, нажать **V** — в окне голосового чата не должно быть надписи о недоступности
сервера; в логе сервера строка `Voice chat server started at port 24454`.

## Вариант B: платный хостинг

На что смотреть при выборе тарифа:
- **RAM**: 6–8 ГБ для средней сборки, 10–12 ГБ для тяжёлой (Create, большие тех-моды, много игроков).
- **CPU**: важна однопоточная частота (сервер Minecraft в основном однопоточный) — Ryzen 7000/9000 или
  Intel последних поколений лучше «многоядерных» Xeon старых поколений.
- **Расположение** — ближе к игрокам (пинг).
- **Доступ к файлам** (SFTP/файловый менеджер), выбор версии Java и загрузчика, автобэкапы.
- Возможность поставить свою сборку (zip / server pack), а не только из каталога хостинга.

## Офлайн-режим и защита ников

Решение владельца: часть игроков заходит с офлайн-аккаунтов (Prism → «Добавить офлайн»), поэтому сервер работает с
**`online-mode=false`**. Серверный пакет (`export-pack.sh`) кладёт `server.properties.default` с этой строкой;
`start.sh`/`start.bat` копируют его в `server.properties`, только если файла ещё нет — настройки хоста при обновлении
пакета не затираются. Если сервер у хоста уже создан — просто поставить `online-mode=false` в `server.properties`
(на платном хостинге — в панели).

## Необязательные моды (WorldEdit выключен)
Моды с `[option] optional=true, default=false` (сейчас — WorldEdit) серверный пакет и `scripts/test-server.sh` кладут не в `mods/`, а в **`mods/optional/`**
(Forge вложенные папки не читает) — сервер без них не держит ≈2,7 ГБ кучи WorldEdit и стартует на ≈2 минуты быстрее.
Включить на время переноса постройки: перенести `mods/optional/worldedit-mod-7.2.15.jar` в `mods/`, перезапустить (+2,7 ГБ памяти, первый старт дольше);
закончили — вернуть jar в `mods/optional/` и перезапустить. Команды для игроков-операторов — `docs/friends.md`, «Перенос построек».

## Сторож тиков (`max-tick-time`)
Когда включён WorldEdit (по умолчанию выключен), он на старте делает один тик дольше 60 с (перебирает состояния всех блоков сборки); по умолчанию `max-tick-time=60000`, и сторож
сервера (ServerHangWatchdog) убивает процесс примерно через минуту после `Done` — в логе «Killed», а в `crash-reports/` запись
«a single server tick took 60.00 seconds». Серверный пакет и `scripts/test-server.sh` кладут **`max-tick-time=-1`** (сторож выключен)
в новый `server.properties`; у уже созданного сервера или на платном хостинге поставить эту строку в `server.properties` (в панели) вручную.
- **Подмена ника**: в офлайн-режиме UUID выводится из ника, проверки владения ником нет — любой, знающий ник (в том
  числе оператора!), зайдёт под ним. Закрывает мод **Sol's AuthLogin** (`pack/mods/sols-authlogin`, side=server): до
  `/register` / `/login` игрок заморожен; пароли хранятся хэшем SHA-256 с солью, есть лимит попыток и временная блокировка.
  Конфиг — `config/` сервера после первого запуска. Забытый пароль сбрасывает хост через конфиг/данные мода.
  Клиентская часть мода необязательна (нужна только для токен-автовхода) — в клиентскую сборку не кладём.
- **Белый список** (дополнительно, не вместо пароля): `white-list=true` в `server.properties` и `/whitelist add <ник>`
  для каждого друга. Отсекает посторонних, но от подмены ника не защищает (ник знают все). Оператору (`/op`) в
  офлайн-режиме особенно важен пароль: оппиться он по нику.
- **Ограничения**: нет скинов с Mojang (у офлайн-игроков стандартный скин, если клиентский скин-мод не настроен);
  нет проверки владения аккаунтом; смена ника = новый игрок. **Simple Voice Chat** в офлайн-режиме работает: он
  привязывается к игроку внутренним секретом, а не сессией Mojang.
- Порт 25565 лучше не светить публично (playit/Tailscale ограничивают круг) — иначе сервер без лицензионной
  проверки открыт всем с адресом.

## Что потребуется от сборки в любом случае
`scripts/export-pack.sh` собирает оба пакета в `dist/` (инструкция для игроков — `docs/friends.md`):
- Серверный пакет `*-server.zip`: только моды со стороной `both` и `server`, конфиги, установщик Forge,
  `start.sh`/`start.bat`. Открыть порты: `25565/TCP` (игра) и `24454/UDP` (голос).
- Клиентский пакет `*.mrpack`: все моды `both` + `client`, импортируется в Prism Launcher / Modrinth App.

## Автообновление сервера с git (mm-autoupdate; поток 67, сборка 2026.10.26-4)
Задача владельца: сервер на Millida должен подтягивать свежую сборку из GitHub при каждом перезапуске — как клиент через
packwiz-installer (README). На Millida команду «перед стартом» задать нельзя (панель сама собирает команду запуска Forge; есть только
«Своё ядро», расписание и `JVM_XX_OPTS`), поэтому обновление делает **серверный мод `mm-autoupdate`** (`mods-src/mm-autoupdate`,
`pack/mods/mm-autoupdate.pw.toml`, `side = "server"`, клиенту не ставится).

### Как работает
1. При **остановке** сервера (`ServerStoppedEvent`: мир уже сохранён, игроки отключены, до выхода из JVM) мод запускает в корне сервера
   `java -Xmx1G -jar packwiz-installer-bootstrap.jar --bootstrap-main-jar packwiz-installer.jar --bootstrap-no-update -g -s server <pack.toml>`
   и ждёт его (по умолчанию до 600 с). Ссылка по умолчанию — `pack/pack.toml` ветки `claude/affectionate-davinci-4gddoh` (raw GitHub).
   Вывод установщика идёт в лог сервера строками `[mm_autoupdate] packwiz: …`.
2. Если `packwiz-installer-bootstrap.jar` / `packwiz-installer.jar` в корне нет — мод скачивает их с GitHub Releases (v0.0.3 / v0.5.14)
   и сверяет sha256 (зашиты в `Updater.java`; `export-pack.sh` читает оттуда же и кладёт оба jar в `*-server.zip`). `--bootstrap-no-update`:
   bootstrap не ходит в GitHub API (лимит 60 запросов/час на IP хостинга), версия установщика поднимается только через конфиг или новый мод.
3. К следующему старту `mods/`, `config/`, `kubejs/`, `defaultconfigs/` и модели YSM уже свежие. Удалённые из сборки моды установщик удаляет
   сам (по своему манифесту `packwiz.json` в корне сервера).
4. После успешного обновления мод чистит `mods/`: **удаляет `*-client.jar`** (клиентские jar сборки — `mm-perf`, `ru-lang`; packwiz-installer
   не знает сторону простых файлов индекса и ставит их на сервер) и **переносит `worldedit-*.jar` в `mods/optional/`** (без GUI packwiz-installer
   включает все необязательные моды — см. «Необязательные моды»). Установщик замечает, что этих файлов нет, и качает их заново при каждом
   прогоне (~7 МБ: WorldEdit 5,8 МБ, ru-lang 1,1 МБ, mm-perf) — терпимо. Списки — `remove_after` / `disable_after` в конфиге.
   Включить WorldEdit насовсем: убрать `worldedit-*.jar` из `disable_after` и перенести jar в `mods/`.
   Затем мод убирает **дубли**: jar в `mods/` с тем же `modId` (из `META-INF/mods.toml`), что у файла из манифеста `packwiz.json`, но сам
   не из сборки — удаляется (оборванное обновление могло оставить старую и новую версию одного мода, а Forge на дублях не стартует).
   Чужой мод хоста с уникальным `modId` не трогается.
5. Итог последнего запуска — файл `mm-autoupdate.status` в корне (`ok <время> version=<версия сборки>` или `failed … exit=N/timeout`).

### Что обновление не трогает
- Всё, чего нет в сборке: `world/`, `server.properties`, `eula.txt`, `ops.json`, `whitelist.json`, данные модов, `mods/optional/`, `logs/`, бэкапы.
- `config/voicechat/voicechat-server.properties` помечен в `pack/index.toml` **`preserve = true`**: packwiz-installer кладёт его только если
  файла ещё нет — порт голоса Millida (своя цифра, 24454 выбрать нельзя) не затирается. `packwiz refresh` этот флаг сохраняет (проверено).
- Файл сборки, который правили на сервере, перезаписывается только когда **его версия в сборке изменилась** (хэш в `index.toml`); пока
  сборка его не меняла, установщик файл не трогает. Исключение — самый первый запуск без `packwiz.json`: тогда сверяются все файлы и
  все отличающиеся от сборки приводятся к ней (кроме `preserve`). Поэтому правки конфигов, которые должны жить на сервере, вносим в `pack/`.
- Файлы, совпадающие со сборкой по хэшу, не скачиваются (на сервере из `*-server.zip` первый прогон ничего не качает, кроме
  `options.txt`, `resourcepacks/*.zip` (9 МБ), клиентских jar и WorldEdit — их тут же обрабатывает п. 4).

### Если обновление оборвалось
Перед запуском установщика мод пишет маркер `.mm-autoupdate.updating` и снимает его только после успеха. Если панель убила процесс по
таймауту остановки или сеть отвалилась, при следующем старте (`FMLDedicatedServerSetupEvent`, до загрузки мира и до shutdown-хука
сервера) мод по маркеру **повторяет обновление и завершает процесс с кодом 0** (`retry_on_start = true`) — запущенная Java уже держит старые
jar, поднимать мир на неполном наборе модов нельзя (с `-Dfml.queryResult=confirm` это ещё и потеря предметов исчезнувших модов). В консоли —
`ЗАПУСТИТЕ ЕГО СНОВА`; на Millida нажать «Запустить» (или включить автоперезапуск). Если и повтор не удался (нет сети), сервер стартует как есть,
в логе `ERROR`, маркер остаётся — проверить `mm-autoupdate.status` и `mods/`. Обычная ошибка сети при остановке запуску не мешает: лог + статус.
**Уточнить у Millida:** сколько секунд панель ждёт после `stop`, прежде чем убить процесс (остановка нашей сборки сама по себе
~1 мин на сохранение + обновление; обычный прогон без изменений — секунды, большое обновление — минуты) и перезапускает ли она сервер после выхода с кодом 0.

### Windows
Запущенная Java на Windows держит jar открытыми — заменить их при остановке нельзя. Мод пишет предупреждение и ничего не делает
(`run_on_windows = false`). Для сервера на ПК друга обновляет **`start.bat`/`start.sh` перед запуском** тем же кодом
(`java -cp mods/mm-autoupdate-*.jar dev.mcmoded.autoupdate.Cli --windows`; пропустить — `MM_NO_UPDATE=1`), ошибка сети запуску не мешает.

### Конфиг `config/mm-autoupdate.toml` (создаёт Forge при первом запуске)
| Ключ | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `true` | обновлять при остановке |
| `pack_url` | raw-ссылка на `pack/pack.toml` ветки сборки | откуда брать сборку |
| `timeout_seconds` | `600` | ждать установщик; дольше — убить, повтор на старте |
| `retry_on_start` | `true` | доделать прерванное обновление на старте и выйти с кодом 0 |
| `run_on_windows` | `false` | пробовать на Windows |
| `remove_after` | `["*-client.jar"]` | что удалить из `mods/` после обновления |
| `disable_after` | `["worldedit-*.jar"]` | что перенести в `mods/optional/` |
| `installer.bootstrap_jar/url/sha256`, `installer_jar/url/sha256` | v0.0.3 / v0.5.14 | откуда взять установщик, если его нет |
| `installer.installer_update` | `false` | разрешить bootstrap спрашивать GitHub API о новой версии |
| `installer.java_path`, `java_args` | java сервера, `-Xmx1G -Djava.awt.headless=true` | чем запускать (установщик держит каждый скачиваемый файл в памяти целиком) |

Проверить вручную на остановленном сервере: `java -cp mods/mm-autoupdate-0.1.0.jar dev.mcmoded.autoupdate.Cli` (на Windows добавить `--windows`;
код 0 — обновлено, 1 — ошибка). Выключить: `enabled = false` или убрать jar из `mods/`.

### Первое включение на Millida
1. Залить по SFTP `mods/mm-autoupdate-0.1.0.jar` (или распаковать новый `*-server.zip`, в нём уже и установщик). `packwiz-installer*.jar`
   класть не обязательно — мод скачает.
2. Остановить сервер из панели: в консоли `[mm_autoupdate] обновление сборки (stop): …`, затем строки `packwiz: …` и
   `обновление завершено, версия сборки 2026.10.26-4`. Первый прогон сверяет все файлы по хэшам (~1,5 ГБ, секунды на NVMe).
3. Запустить. Дальше каждый перезапуск = свежая сборка; версия на сервере — `config/mm_pack_version.txt` и `mm-autoupdate.status`.
4. Порт голоса в `config/voicechat/voicechat-server.properties` при этом сохраняется (`preserve`), `server.properties` — не в сборке.

### Как проверено (2026-10-26, Windows, Forge 47.4.26, голый сервер + мод; Linux с полной сборкой — см. compat.md)
- Ручной прогон `Cli` на тестовом паке (два варианта пака на локальном HTTP): установщик скачан и сверен по sha256; `preserve`-файл
  (`port=9999`) не тронут ни при первом прогоне, ни при смене версии пака; изменённый в паке `other.toml` перезаписан; `*-client.jar` удалён;
  WorldEdit (optional, default=false) установлен и перенесён в `mods/optional/`; повторный прогон без изменений — секунды; ошибка (нет `pack.toml`) →
  код 1, маркер остаётся, `mm-autoupdate.status = failed`; без `--windows` на Windows — предупреждение и код 2; дубль мода удалён.
- В Forge: `stop` → мир сохранён → `[mm_autoupdate] обновление сборки (stop)` → строки `packwiz:` → `обновление завершено`; на Windows без
  `run_on_windows` — предупреждение; с маркером на старте — повтор, обновление, `ЗАПУСТИТЕ ЕГО СНОВА`, выход с кодом 0 до `Done`.
- `packwiz refresh` сохраняет `preserve = true` в `index.toml`; в этом Windows-checkout `core.autocrlf=true` — перед `refresh` файлы `pack/`
  приведены к LF, иначе хэши индекса считаются по CRLF и расходятся с тем, что отдаёт GitHub (клиенты получили бы «index file hash is invalid»).

### Почему мод, а не «обёртка-ядро»
Рассмотрен второй вариант: в панели выбрать «Своё ядро (свой .jar)» и подсунуть обёртку, которая сначала запускает packwiz-installer,
а потом Forge дочерним процессом (`java @user_jvm_args.txt @libraries/net/minecraftforge/forge/1.20.1-47.4.26/unix_args.txt nogui`),
пробрасывая консоль и сигналы.
- Плюс обёртки: обновление **до** старта — нет проблемы «убили в середине обновления», не нужен повтор на старте, и на Windows работает.
- Минусы: панель не знает, что это Forge — память и флаги (`-Xmx`, `JVM_XX_OPTS`) достаются обёртке, а не дочернему серверу, их надо
  пробрасывать самим; `stop` из панели и SIGTERM надо ловить и передавать ребёнку (иначе панель убьёт обёртку, а сервер останется сиротой
  или не сохранит мир); две JVM; поддержка Millida про «своё ядро» ничего не обещает, а при смене версии Forge/Java обёртку придётся
  переделывать. Это «ядро», живущее вне нашей сборки: обновить его сам packwiz не может.
- Мод — обычный серверный мод сборки: обновляется вместе с ней, панель видит обычный Forge, всё остальное штатно. Цена — обновление
  при остановке (как у любого панельного хостинга без хука) и маркер с повтором на случай обрыва. Если на Millida окажется, что панель
  убивает процесс сразу после `stop`, вернуться к обёртке (или к обновлению по расписанию: команда панели `stop` + автозапуск).
