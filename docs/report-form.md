# Приём отчётов от игроков: форма, Таблица, статусы, приёмщик

Репозиторий публичный, поэтому **отчёты, ники, логи, скриншоты и ссылки spark в git, в публичных Issues и на публичных страницах не хранятся**.
Всё это живёт только в приватной Google Форме, её Таблице и на Google Диске владельца. Ссылка на форму уходит друзьям лично, в репозиторий
не вписывается (в `docs/whats-new-check.md` стоит заглушка `<ссылка на форму — у хоста>`).

Решения (владелец, 2026-10-18, через Координатора): одна форма, файл в ней необязателен; номера отчётов R-###; статусы и сводка в Таблице;
маскировка ника/IP/путей в скрипте диагностики; GitHub Issues выключены.

## Что нужно знать про Google Формы
- **Любой вопрос с загрузкой файла включает обязательный вход в Google для всех, кто отвечает на форму**, даже если сам вопрос необязательный.
  Если друзья без Google-аккаунта — убрать вопрос «Файлы» и оставить поле «Ссылка на файлы» (облако с доступом по ссылке) или принять zip лично.
- Загруженные файлы попадают в папку Диска владельца «<название формы> (File responses)». Эту папку **не открывать по ссылке и не делиться ею**.
- Адрес почты собирается (подтверждённый, нужен вход в Google); видеть ответы и адреса — только владелец (и тот, кому он выдал доступ к Таблице). Адрес никогда не публикуется.

## 0. Быстрый путь: один скрипт делает форму, Таблицу и связь (владельцу, ~5 минут)
Клики, по порядку:
1. Откройте sheets.google.com → *Пустая таблица*. Назовите «Отчёты Minecraft_moded (приватно)». Доступ — только вы, «доступ по ссылке» не включать.
2. В Таблице: меню *Расширения → Apps Script*. В открывшемся редакторе слева файл `Code.gs`: выделить всё (Ctrl+A), удалить, вставить целиком содержимое
   `scripts/report-sheet/Code.gs` из репозитория. Нажать значок дискеты (*Сохранить проект*).
3. Вверху в выпадающем списке функций выбрать **`bootstrap`** → кнопка **Выполнить**. Google спросит доступ: *Проверка разрешений → выбрать свой аккаунт →
   «Google не проверил это приложение» → Дополнительные → Перейти (небезопасно) → Разрешить* (это ваш собственный скрипт; нужны права на Формы и Таблицы).
4. Подождать ~10–30 секунд. В Таблице появятся листы **Начало, Сводка, По номеру, По автору, По людям, Кто что ждёт** и лист ответов формы.
5. Лист **«Начало»**: там ссылка на форму для друзей и ссылка на редактор формы. Это приватная Таблица; ссылки отсюда **в git не копировать**.
6. Ручные шаги (они же написаны на листе «Начало»; скрипт их сделать не может — проверено по документации Apps Script):
   - **Адреса: обязательно.** Редактор формы (ссылка со листа «Начало») → вкладка **Настройки** → блок **Ответы** → **Собирать адреса электронной почты** →
     выбрать **Подтверждённые**. Скрипт только включает сбор адресов (`setCollectEmail(true)`), тип в Apps Script не выбирается.
   - **Файлы: по желанию.** Редактор формы → внизу круглая кнопка **+** (*Добавить вопрос*) → тип **Загрузка файла** → название «Файлы», выключить *Обязательный вопрос*
     → сохранить условия загрузки (до 5 файлов, до 1 ГБ). Скрипт этот тип вопроса создавать не умеет. Без него друзья присылают архив ссылкой в поле «Ссылка на файлы».
   - *Ответы → ⋮ → Получать уведомления о новых ответах по эл. почте*.
7. Проверка: откройте ссылку для друзей, отправьте тестовый отчёт — в листе ответов должна появиться строка с номером **R-001**, статусом «новый», а на листах «По номеру»/«По людям» — эта же строка.
   Тестовый отчёт остаётся как R-001 (счётчик не сбрасывается): отметьте его статусом «не баг» с пояснением «тест» или просто примите за первый.
8. Повторный запуск `bootstrap` форму **не дублирует** (id формы хранится в свойствах документа): он заново применит описание/текст подтверждения и перерисует листы. Обновлённый `Code.gs`: вставить, снова запустить `bootstrap`.

**Лист ответов — «Таблица» Google (Tables), и `bootstrap` мог упасть на середине.** Google сам оформляет лист ответов формы как «Таблицу»,
а `createFilter()` на таком листе падает («Нельзя применить фильтр к диапазону, который частично пересекается с таблицей»).
Поэтому в `setup()` триггеры (`onFormSubmit`, ежедневный) создаются первыми, а фильтр, списки, подсветка и закрепление строки — необязательные:
сбой каждого пишется в журнал выполнения (`Logger`, *Выполнения* в Apps Script) и не обрывает остальное; лист «Начало» пишется даже при сбое `setup()`.
Если `bootstrap` всё же упал — просто **запустите его ещё раз**: повторный запуск безопасен (форму не дублирует, триггеры пересоздаёт).
Фильтр при сбое ставится вручную: *Данные → Создать фильтр* — или пользуйтесь фильтром самой «Таблицы».
**Локаль Таблицы.** `setup()` ставит локаль `en_US` (`setSpreadsheetLocale`) до записи формул: формулы написаны с запятой как разделителем аргументов, а в русской локали разделитель `;`, и `COUNTIF`, `COUNTIFS`, `QUERY` дали бы `#ERROR!`.
На даты и формат чисел это почти не влияет (в ячейках может поменяться только вид десятичного разделителя и формат даты по умолчанию). Шаг не необязательный, выполняется на каждом запуске, смена записывается в журнал.
Листы «По номеру», «По автору», «Кто что ждёт» показывают «Нет отчётов», пока ответов нет (`IFERROR(QUERY(…))`). Подписи на «Сводке» — значения, формулы только в колонке B.
**Пересчёт формул.** Формулы «Сводки» и служебных листов пишет `writeFormulas_()`: при `setup()`, после каждого отчёта из формы (`onFormSubmit`) и в ежедневной сверке (`fillMissing`), затем `SpreadsheetApp.flush()`. Перезапись дешёвая и идемпотентная (листы не очищаются); без неё Таблица после новой строки формы показывала старые значения. Диапазон QUERY строится по текущему числу колонок листа ответов (после ручного вопроса «Файлы» это A2:AB и т. д.), колонки ищутся по заголовкам.
**Письмо автору сразу после отправки (решение владельца В43 «а»).** `onFormSubmit` после присвоения R-### шлёт `MailApp.sendEmail` на подтверждённый адрес из колонки адреса. Тема «Отчёт R-### принят — Minecraft_moded»; текст: «Спасибо! Ваш отчёт принят, номер R-###. Статус — на странице report-status: <ссылка на `docs/report-status.md`>. Хост ответит в чате.» Ника, текста отчёта и других данных автора в письме нет.
Защиты: адрес проверяется простым regex (без пробелов, переводов строк и запятых, ≤ 254 символов, не начинается с `= + - @`); письмо не уходит повторно (колонка «Письмо отправлено (дата)»); проверяется `MailApp.getRemainingDailyQuota()`; `fillMissing` писем не шлёт; сбой отправки не роняет триггер (причина в «Заметке» без адреса и в журнале выполнений).
При первом запуске Google запросит разрешение «Отправлять письма от вашего имени» (минимальная область MailApp); лимит — около 100 писем в день для обычного аккаунта. Выключатель: `CFG.SEND_CONFIRMATION = false` в `Code.gs`. **Важно: письма безопасны только при типе сбора адресов «Подтверждённые» (ручной шаг 1 в «Начале»).** При типе «Введённые пользователем» любой может вписать чужой адрес, и скрипт отправит на него письмо (фиксированный текст, но это рассылка с вашего аккаунта): тогда выключите `CFG.SEND_CONFIRMATION` или переключите тип. Если Code.gs обновлён у уже работающей Таблицы, запустите `bootstrap` ещё раз и согласитесь на новое разрешение: пока оно не выдано, `onFormSubmit` не сможет отправить письмо (причина — в «Заметке» строки и в журнале выполнений). Ссылка в письме — `CFG.STATUS_URL` (публичный репозиторий; при приватном репозитории друзья её не откроют).
**Формулы в тексте из формы.** Ник, адрес и пр. из публичной формы попадают на «По людям» через `setValues`: значения, начинающиеся с `=`, `+`, `-`, `@`, табуляции или `\r`, получают впереди апостроф (`safeText_`), и дополнительно колонки стоят в текстовом формате. Если на «По людям» у такого ника виден ведущий `'`, это ожидаемо (защита важнее вида).

Что создаёт скрипт: форму с полями из таблицы ниже, описание с предупреждением про адрес, текст подтверждения (§1 п. 5), сбор адресов, привязку к этой Таблице, листы, проверки значений,
подсветку, триггеры «при отправке формы» и ежедневный. **Не проверено в настоящем Google** — первый запуск владельцем и есть проверка; если что-то пойдёт не так, остальные разделы описывают то же вручную.

## 1. Создать форму вручную (запасной путь, ~15 минут)
1. forms.google.com → *Пустая форма*, название «Minecraft_moded — отчёт о проблеме».
2. *Настройки → Ответы*: «Собирать адреса эл. почты» — **Подтверждённые** (решение владельца В42: так видно, с какого адреса пришёл отчёт, и можно вести историю по каждому человеку);
   «Отправлять копию ответа» — выкл; «Ограничить одним ответом» — выкл. Это отменяет прежнее «выкл». Нужен вход в Google (как и для загрузки файлов).
   Запасной путь: если у друга нет Google-аккаунта, он пишет владельцу, и **владелец сам заносит отчёт** в форму/Таблицу (адрес не заполняется, группировка по нику).
3. Описание формы (вставить как есть): *«Опишите проблему. Логи и скриншоты — по желанию, лучше файлом `diag-Player-….zip` от
   `collect-diagnostics.bat` (ник и IP в нём заменены). Не вставляйте пароли, адрес дома, реальное имя и IP в текст. Ответы видит только хост. Адрес виден только хосту, не публикуется; нужен вход в Google.»*
4. Поля (порядок сверху вниз, список ниже):

| № | Поле | Тип | Обязательно | Подсказка |
|---|---|---|---|---|
| 1 | Ник / имя для связи | Короткий текст | **да** | Как к вам обратиться. Ник виден только хосту. Отчёты без имени не принимаются |
| 2 | Псевдоним из диагностики | Короткий текст | нет | `Player-xxxx` из конца окна скрипта диагностики (по нему сопоставим zip с вами) |
| 3 | Версия сборки | Короткий текст | **да** | Дата последнего обновления сборки или номер из Prism. Не знаете — «не знаю» |
| 4 | Пункт «Что нового» | Раскрывающийся список | нет | W1…W10 из `docs/whats-new-check.md`, «другое» |
| 5 | Где играли | Один из списка | **да** | Одиночная игра / сервер друзей |
| 6 | Мод или предмет | Короткий текст | нет | Подсказка Jade при наведении или вкладка *Mods*. Не знаете — «не знаю» |
| 7 | Что не работает / что хотите видеть | Абзац | **да** | Проблема: что делали, что ожидали, что получилось. Пожелание: что хотели бы увидеть и зачем |
| 8 | Шаги, чтобы повторить | Абзац | нет | 1–2–3. Не повторяется — напишите |
| 9 | Как часто | Один из списка | нет | Один раз / иногда / каждый раз |
| 10 | Категория | Один из списка | **да** | краш/вылет / фризы/лаги / мод/механика / модели/графика / звук/голос / сервер/вход / другое / **пожелание / идея** (эти значения — точно, по ним сортируем и отделяем пожелания от багов) |
| 11 | Ссылка spark | Короткий текст | нет | При лагах: в мире `/spark profiler start`, 2–3 минуты игры, `/spark profiler stop`, ссылку из чата сюда |
| 12 | Ссылка на файлы | Короткий текст | нет | Если файл большой: ссылка на облако «доступ по ссылке», срок — неделя |
| 13 | Файлы | Загрузка файлов | нет | `diag-Player-….zip`, `crash-….txt`, скриншоты (F2). До 5 файлов, до 1 ГБ каждый. **Включает вход в Google** (см. выше) |
| 14 | ОС, видеокарта, память для игры | Короткий текст | нет | Например: Windows 11, RTX 2060, 8192 МБ |

5. *Настройки → Презентация → Сообщение подтверждения* (вставить как есть): *«Спасибо! Номер отчёта и ответ пришлём в чат в течение суток; статус — на странице report-status»*
   (Ссылку на страницу в текст не вставляем: она публичная, но «report-status» друзья найдут в `docs/report-status.md` репозитория.)
   «Ответ в течение суток» — обязательство хоста/приёмщика: его держит оранжевая подсветка в Таблице (раздел 3).

## 2. Привязать Таблицу (при ручном пути; `bootstrap` делает это сам)
1. В форме вкладка *Ответы* → зелёный значок «Связать с Таблицами» → *Создать таблицу*. Название — «Отчёты Minecraft_moded (приватно)».
2. Доступ к Таблице — только вы. Не включать «доступ по ссылке».
3. *Ответы → ⋮ → Получать уведомления о новых ответах по эл. почте* — вы увидите новый отчёт сразу.

## 3. Номера R-###, статусы, подсветка (скрипт; при быстром пути `setup()` вызывается из `bootstrap()`)
1. В Таблице: *Расширения → Apps Script*. Удалить содержимое файла `Code.gs`, вставить целиком файл `scripts/report-sheet/Code.gs` из репозитория.
2. Сохранить, в списке функций выбрать `setup` → *Выполнить*. Google попросит доступ («приложение не проверено» — это ваш собственный
   скрипт: *Дополнительные настройки → Перейти → Разрешить*). Запускается один раз.
3. Скрипт добавляет колонки: **№, Статус, Ответственный (поток/PR), Исправлено в версии, Дата изменения, Заметка, Статус изменён (дата),
   Мод для публичной страницы, Описание для публичной страницы, Пояснение для публичной страницы, Ответ автору, Ответ отправлен (дата)**, а также:
   - при каждом новом ответе даёт номер R-001, R-002… (счётчик не сбивается, если вы удалите строку) и статус «новый»;
   - каждый день в 9 утра проверяет, что у всех строк есть номер и статус (если сбой — проставит);
   - список статусов: **новый → принят → в работе → исправлено**, а также **дубль**, **не баг**, **нужны данные**, **отложено**; у пожеланий свой набор (см. раздел «Пожелания» ниже);
   - подсветку: **оранжевым — строки, где есть номер, а ответ автору не отправлен** (колонка «Ответ отправлен (дата)» пуста или старше «Статус изменён (дата)»;
     после смены статуса строка снова становится оранжевой, пока вы не отправите ответ и не поставите дату); красным строки в статусах «новый / принят / в работе / нужны данные» (и без статуса), если «Дата изменения» старше 7 дней;
     зелёным — закрытые (исправлено, дубль, не баг). «Отложено» красным не краснеет;
   - «Дату изменения» при правке статуса, ответственного, версии или заметки;
   - лист **Сводка**: баги — получено, обработано, висит, висят дольше 7 дней, отложено; пожелания — всего, открыто, реализовано, отклонено, ждут решения владельца (раздельно, без смешения);
     общие строки — без номера (должно быть 0), ждут ответа автору, дата. Баги и пожелания различаются по колонке «Категория» («пожелание…» = пожелание).
   Если скрипт обновляется на уже работающей Таблице: вставить новый `Code.gs`, снова запустить `setup()`; у старых строк «Статус изменён» станет датой запуска,
   поэтому они будут оранжевыми, пока не проставите «Ответ отправлен (дата)» (или не отправите ответы).
   - колонку «Адрес эл. почты» (если форма сама её не создала — `setup()` добавит пустую для ручного ввода) и лист **«По людям»**: одна строка на человека
     (группировка по адресу, без адреса — по нику): адрес и ник, всего отчётов и сколько открытых, номера R-### со статусами, дата последнего ответа автору, есть ли неотвеченные.
     Пересобирается при новом ответе, раз в день и из меню *Отчёты → Обновить «По людям»*;
   - колонку «Категория» (список из 8 значений: 7 категорий проблем и «пожелание»; форма пишет «пожелание / идея», скрипт опознаёт по началу слова), **фильтры** на листе ответов и служебные листы (формулы, пересчитываются сами):
     **«По номеру»**, **«По автору»** (сортировка по имени из формы, затем по номеру), **«Кто что ждёт»** (автор и число его открытых отчётов).
     В них есть ники: **листы только для владельца**, Таблицей ни с кем не делиться, листы не публиковать и не копировать в git/чат.
   Колонки публичной страницы и ответов заполняются **вручную** (см. разделы 6 и 8); скрипт их не трогает.
4. Без скрипта (запасной вариант): номер формулой `="R-"&TEXT(ROW()-1;"000")` в колонке «№» (минус: удалили строку — номера сдвинутся),
   список статусов — *Данные → Настроить проверку данных → Список*, подсветка — *Формат → Условное форматирование*.
5. Правило заполнения: «Ответственный» — поток (`Поток N`) или PR (`#123`); «Исправлено в версии» — дата сборки или номер из `pack.toml`,
   с которой исправление доступно игроку.

## 4. Статусы (значение)
| Статус | Когда ставить |
|---|---|
| новый | Пришло, никто не смотрел (ставится автоматически) |
| принят | Прочитан, воспроизводится или признан проблемой, виновник известен или ищется |
| в работе | Есть ответственный поток или PR |
| исправлено | Исправление влито; в «Исправлено в версии» — когда его получит игрок |
| дубль | Тот же симптом и мод, что у другого отчёта; в «Заметке» — `дубль R-012` |
| не баг | Так задумано или это настройка; в «Заметке» — что сказать автору |
| нужны данные | Нужны логи/шаги; автору пишет владелец; через 14 дней без ответа закрыть как «не баг» с заметкой |
| отложено | Проблема признана, но сейчас не делаем (мало данных, редкая, ждём обновления мода). В «Пояснении для публичной страницы» — почему и что нужно, чтобы вернуться; красным не краснеет |

## 5. Процесс приёмщика: «ничего не пропущено»
Приёмщик — человек или сеанс, которому владелец даёт данные. Он **не публикует и не коммитит** чужое.

**Регулярная сверка (раз в день или раз в N дней по договорённости):**
1. Посмотреть лист «Сводка»: получено N, обработано M, висит K, старше 7 дней X, без номера Y (должно быть 0).
2. Разобрать все строки «новый» и красные: выставить статус и ответственного, найти дубли.
3. Сводка владельцу (в чат, не в git):
   `Получено N, обработано M, висит K, из них старше 7 дней X. Новых: …, нужны данные: …, критичных (вылеты, потеря мира): … `
   Ниже — таблица «кластер, сколько отчётов (R-###), версия, мод, вероятная причина, что снять дополнительно».
4. Исправленное: отметить «исправлено» и версию; в публичные документы идёт только «исправлено по отчёту R-012» (без ника).
5. Оранжевые строки: отправить ответ автору (шаблоны — раздел 6), поставить «Ответ отправлен (дата)». Публичные колонки заполнить для каждой строки (раздел 8).

**Откуда приёмщик берёт данные.** В этом сеансе есть коннектор Google Drive (`mcp__…__search_files`, `read_file_content`, `download_file_content`),
но я его не вызывал, и у других облачных потоков он может быть недоступен. Поэтому два режима:
- **Режим А (по умолчанию): ведёт владелец.** Сводку берёт со вкладки «Сводка» и фильтров Таблицы (по статусу и красным строкам);
  приёмщик получает от владельца только выжимку (номер, версия, мод, симптом, 3–10 строк лога без личного).
- **Режим Б: экспорт CSV.** Раз в N дней владелец делает *Файл → Скачать → CSV* (лист ответов) и отдаёт приёмщику вне репозитория.
  Приёмщик кладёт его в `mktemp -d` вне репо, читает Python с `-I`, ничего не запускает из файлов, по завершении `rm -rf`.
- **Режим В (только если владелец сам разрешит): коннектор Drive** даёт приёмщику доступ к конкретной Таблице. Это значит, что тексты отчётов
  и ники проходят через сеанс Claude; логи по-прежнему не пересылать другим сеансам целиком.

**Правила хранения:** ники и логи — только в Таблице и на Диске; в репо, Issues, PR, `compat.md` попадают обобщения («у N игроков при X происходит Y,
мод Z, отчёты R-012, R-015»). Увидели пароль/адрес в ответе — сказать владельцу, он удалит строку.
Для потоков-исправителей выжимка: номер R-###, версия сборки, мод и версия, симптом, шаги, 3–10 строк лога с замаскированными данными, сколько игроков.

## 6. Обратная связь авторам
- Публично: страница `docs/report-status.md` (раздел 8) и строки «исправлено по отчёту R-012» в `docs/whats-new-check.md` / `docs/compat.md`. Ников нет.
- Лично автору отвечает скрипт (автоответ ниже); если нужен ответ самого владельца, приёмщик ставит `[ЧЕРНОВИК]`. Срок: номер и первый ответ — в течение суток.
- Готовый текст кладётся в колонку «Ответ автору». **Автоответ (решение владельца В44 «б»):** скрипт сам отправляет его автору, без предварительного одобрения владельца.
  - Таймер `sendReplies` — раз в 15 минут (создаётся в `setup()`/`bootstrap`, повторный запуск триггеры не плодит). Колонку заполняет Связь через Sheets API; такая запись `onEdit` не вызывает, поэтому нужен именно таймер.
  - Уходит строка, где одновременно: «Ответ автору» не пуст; текст не начинается с `[ЧЕРНОВИК]` (регистр и ведущие пробелы не важны); «Ответ отправлен (дата)» пусто; адрес из колонки адреса формы корректен; `CFG.SEND_REPLIES = true`.
  - **Метка `[ЧЕРНОВИК]`:** Связь ставит её в начале текста, когда нужен ответ самого владельца. Такой текст не уходит; владелец правит его, убирает метку — и на ближайшем запуске таймера письмо уйдёт.
  - **Как писать ответ:** сначала пишите текст с меткой `[ЧЕРНОВИК]` в начале, **снимайте метку, только когда текст готов** — с этой минуты (до 15 минут) он уйдёт автору сам. Лимит текста — 4000 символов (длиннее обрезается).
  - Письмо: тема «Ответ по отчёту R-### — Minecraft_moded» (только номер), тело — текст ответа (plain text, до 4000 символов), пустая строка и «Статус: <ссылка>». Без вложений, cc/bcc; replyTo не меняется. Адресат — только колонка адреса формы.
  - После отправки ставится «Ответ отправлен (дата)». **Повторно не шлём:** если владелец позже правит текст, письмо не уходит. Чтобы ответить ещё раз, вручную очистите ячейку «Ответ отправлен (дата)».
  - Лимиты: не больше `CFG.MAX_REPLIES_PER_RUN = 20` писем за запуск; шлётся не больше `getRemainingDailyQuota() − 10` (запас под письма-подтверждения); `LockService` не даёт двум запускам отправить дважды. Ошибка одной строки пишется в «Заметку» (без адреса; одна и та же причина не дублируется) и в журнал, остальные строки продолжаются.
  - **Проверка текста перед отправкой** (те же правила, что у `scripts/report-status.py`): письмо не уходит, если в тексте есть ник/контакт/адрес другого автора с листа ответов (имя самого адресата в обращении допустимо), IP, пути `C:\Users`/`/home/`, `@`-упоминания, HTML-сущности, ссылки Диска/spark/форм, а также любой URL, кроме `CFG.STATUS_URL` и `https://github.com/limanov7kiy/Minecraft_moded`. Причина пишется в «Заметку» без цитаты; поправьте текст — на следующем запуске он проверится заново.
  - Выключатель: `CFG.SEND_REPLIES = false` в `Code.gs`. После обновления `Code.gs` запустите `bootstrap` ещё раз: нужен новый триггер, и Google может снова запросить разрешение на отправку писем — без него `sendReplies` не сработает (причина — в журнале выполнений). Как и с подтверждениями, безопасно только при типе сбора адресов «Подтверждённые».
- В «Ответ отправлен (дата)» дату теперь ставит скрипт; вручную её ставят только для ответа, отправленного не через скрипт.
- **Публичные колонки заполняются отдельно и своими словами**: «Описание для публичной страницы» (что за проблема, без ника и без цитат автора),
  «Пояснение для публичной страницы» (для не баг / отложено / нужны данные — почему или что нужно), «Мод для публичной страницы».
  Текст автора как есть копировать **нельзя**: в нём бывают ник, IP, пути, ссылки. Генератор отсекает очевидное, но не заменяет глаза.

Шаблоны (подставить `R-###`, имя, даты; в `<…>` — своё):

**Принят**
> Привет, <имя>! Твой отчёт принят, номер **R-###**. Мы его посмотрим; статус будет на странице report-status (в репозитории `docs/report-status.md`). Если что-то новое по этой проблеме — пиши с номером.

**Нужны данные**
> <имя>, по **R-###** нужно ещё одно: <что именно: лог последнего запуска / crash-файл / шаги по пунктам / сколько у тебя памяти для игры / повторяется ли у друга>. Как собрать — `docs/diagnostics.md`. Если до <дата, +14 дней> ответа не будет, закроем как «не баг» — но можно вернуться в любой момент.

**Не баг**
> <имя>, **R-###**: это не ошибка сборки. <Почему: так задумано / настройка вот тут / причина на вашей стороне — и что сделать>. Если после этого всё равно не так — напиши, откроем снова.

**Исправлено**
> <имя>, **R-###** исправлено в сборке <дата / номер из pack.toml>. Обновитесь (инструкция — `docs/friends.md`) и проверьте; если не прошло — напишите с этим номером.

**Отложено**
> <имя>, **R-###** пока откладываем: <причина — редкая / не воспроизводится / ждём обновления мода / дороже, чем польза>. Вернёмся, когда <условие>. Статус и причина — на странице report-status.

## 8. Публичная страница статусов: «разберите отчёты»
Решение владельца (В41): процесс решения открыт для ребят. Страница `docs/report-status.md` собирается скриптом `scripts/report-status.py` из CSV Таблицы.
Публикуются **только** колонки: номер, категория (из фиксированного списка), «Описание для публичной страницы», «Мод для публичной страницы», статус, «Дата изменения», «Исправлено в версии» (или PR вида `#123` из «Ответственный»),
«Пояснение для публичной страницы». Ник, контакт, текст автора, ссылки на файлы, spark и вообще всё остальное скрипт не читает в вывод. Строка без публичного описания не публикуется (предупреждение).
Защита: если в публичных полях есть похожее на IP, путь Windows/Linux, URL, ссылку Диска/spark/формы, e-mail, `Player-xxxx` или ник автора — строка не публикуется, в предупреждении только номер и причина.

**Когда владелец говорит «разберите отчёты»:**
1. Владелец даёт приёмщику CSV (*Файл → Скачать → CSV*, лист ответов) — вне репозитория, личным каналом, не в git и не в PR.
2. Приёмщик работает во временной папке **вне репозитория**: `T=$(mktemp -d)`, CSV кладёт туда. Файлы из CSV не открывает и не запускает, читает только Python с `-I`.
3. Для каждой строки: статус, ответственный, дубли; пишет публичные колонки (раздел 6: свои слова, без ника, без цитат автора, без IP/путей/ссылок);
   готовит тексты ответов авторам по шаблонам раздела 6 и **отдаёт их владельцу** (в чат, не в git). Правки в публичных колонках владелец вносит в Таблицу и выгружает CSV заново (или приёмщик правит копию CSV во временной папке, и владелец потом повторяет то же в Таблице).
4. Запуск: `python3 -I scripts/report-status.py "$T/reports.csv"` — перезаписывает `docs/report-status.md`. Прочитать **все предупреждения** и сам файл глазами. Отказ «CSV внутри репозитория» — значит, CSV положен не туда.
5. Коммитит **только** `docs/report-status.md` (`git status` — больше ничего; особенно CSV), PR на ревью. Для строк «исправлено» добавляет в `docs/whats-new-check.md`, раздел «Исправлено по отчётам», `R-012 — исправлено, нужна сборка от <дата>`.
6. Сразу после PR: `rm -rf "$T"` (CSV с личными данными не остаётся ни на диске, ни в сеансе). Если CSV пересылали — удалить и там.
7. Владелец отправляет авторам ответы и ставит «Ответ отправлен (дата)».

Пожелания страница показывает отдельным разделом «Пожелания» (свои сводка, таблицы и статусы, без колонки категории); генератор разделяет их по категории, и баги в этот раздел не попадают (и наоборот). Статус не из набора своей категории («исправлено» у пожелания, «реализовано» у бага) — строка не публикуется, в предупреждении только номер.

Проверка скрипта: `python3 -I scripts/tests/report-status-test.py` (выдуманные данные). Логику Code.gs: `node -e "require('module')._extensions['.gs']=require('module')._extensions['.js']; require('./scripts/tests/report-sheet-test.js')"`.

**Порядок и группы на странице.** Строки идут по R-номеру; открытое и решённое разбито на подразделы по статусу, внизу сводки: категория × открыто/решено и мод × открыто/решено.
**Имена, ники и адреса не публикуются никогда** (решение владельца, В42). Колонки автора на странице нет, группировки по людям на странице нет — «По людям» живёт только в приватной Таблице.
Защита генератора: ник, псевдоним диагностики, адрес почты и контакт режутся на слова (по пробелам, запятым, `@`, `/`; слова от 3 знаков); любое такое слово в публичных полях (без учёта регистра) — строка не публикуется.
Кроме того, блокируются любые e-mail, `@упоминания`, ссылки на t.me / discord / steam / vk и markdown-ссылки `](…)`.

## 9. Режим В: приёмщик через Sheets API (коннектор)
Режим В разрешён владельцем 2026-10-18; исполняет Связь (сессия-посредник). Наружу, потокам и в git передаётся только выжимка по §5.
Таблица «Отчёты Minecraft_moded (приватно)» остаётся приватной; её id и ссылку в git, PR и публичные чаты не вписываем. `bootstrap()` работает в уже созданной пустой Таблице
(привязанный скрипт берёт её через `getActiveSpreadsheet()`, новую не создаёт); пустой лист и ноль ответов ему не мешают.
- **Колонки искать по заголовкам в строке 1, не по буквам** (порядок зависит от формы; адрес из формы идёт второй, если сбор адресов включён).
- **Писать можно только на листе ответов формы**, колонки: «Статус» (строго из списка статусов), «Ответственный (поток/PR)», «Исправлено в версии», «Заметка», «Категория», «Мод для публичной страницы»,
  «Описание для публичной страницы», «Пояснение для публичной страницы», «Ответ автору», «Ответ отправлен (дата)», «Адрес эл. почты» (только при ручном внесении отчёта).
- **Нельзя**: формулы и ячейки листов «Сводка», «По номеру», «По автору», «Кто что ждёт» (это зеркала, запись туда ломает формулу); лист «По людям» (пересобирается скриптом, не править);
  колонки «№» и ответы формы (строки 2+ в колонках самой формы); свойства документа и триггеры; заголовки строки 1.
- **Смена статуса через API не запускает `onEdit`**, поэтому вместе со «Статусом» писать вручную «Дата изменения» и «Статус изменён (дата)» (дата и время, режим USER_ENTERED, например `2026-10-18 14:30:00`),
  иначе строка останется без подсветки и не попадёт в «оранжевые». Отправили ответ автору — «Ответ отправлен (дата)» тем же способом.
- «По людям» после правок обновить: меню *Отчёты → Обновить «По людям»* (владелец) или ждать ежедневной пересборки в 9:00.
- Публичные колонки заполнять по правилам раздела 6 (без ника, адреса, цитат автора); текст автора, адреса и ники приёмщик в чат/PR/git не переносит.

## 10. Пожелания
Решение владельца (2026-10-19): «давай добавим категорию пожелания, где игроки будут писать, что им хотелось бы увидеть; если это не повлияет на баланс — будете реализовывать, если будет влиять — спрашивать меня и будем решать вместе».
Нумерация общая R-### (отдельного W-### нет); пожелание — это категория «пожелание / идея» в форме. Баги и пожелания в Таблице, «Сводке» и на публичной странице считаются раздельно.

**Как это выглядит у автора.** В форме в «Категории» есть пункт «пожелание / идея», общий вопрос называется «Что не работает / что хотите видеть» (подсказка: что хотели бы увидеть и зачем). Сразу после отправки приходит письмо «Спасибо за идею! Номер R-###, статус — на странице report-status» (тема «Идея R-### принята — Minecraft_moded»; ника и текста идеи в письме нет).

**Статусы пожеланий** (первый ставится автоматически, «новый» у пожеланий не бывает):
| Статус | Когда ставить |
|---|---|
| идея | Пришло, никто не смотрел (автоматически) |
| принята | Не влияет на баланс (или владелец разрешил) — будем делать |
| в реализации | Есть ответственный поток или PR |
| реализовано | Влито; в «Исправлено в версии» — когда получит игрок |
| нужно решение владельца | Влияет на баланс или спорно: вопрос В## владельцу (см. ниже) |
| отклонено | Не берём; причину пишем в «Пояснении для публичной страницы» |
| отложено | Не сейчас; причина и условие возврата — в «Пояснении» |

Список в ячейке «Статус» общий для багов и пожеланий (Google не умеет разный список на строку), поэтому Таблица пропустит «исправлено» у пожелания или «реализовано» у бага. Скрипт не запрещает, а ставит на ячейку примечание «статус не подходит категории», а генератор страницы такую строку не публикует (в предупреждении только номер). «Отложено» общий. Зависшими (красным) считаются открытые статусы пожеланий: идея, принята, в реализации, нужно решение владельца; реализовано и отклонено — зелёные.

**Порядок разбора.** Связь по расписанию проверяет новые отчёты (как и баги — §5, §9): для каждого нового пожелания, читая его по правилам §9, она
1. делает публичное описание (своими словами, без ника и цитат, §6) и мод; 
2. относит идею по списку ниже: «можно самим» → статус «принята», ответственный поток, дальше обычный процесс (ветка, PR, ревью) и итог владельцу в сводке; «с владельцем» → статус «нужно решение владельца» и вопрос владельцу;
3. дубли пожеланий закрывает как «отклонено» с пояснением «объединено с R-###» (статус «дубль» у пожеланий нет);
