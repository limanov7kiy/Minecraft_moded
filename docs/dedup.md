# Логические дубли между модами: аудит (этап 1)

Поток 66, 2026-10-26, сборка 2026.10.26-5. Решение владельца (после В54): «Это же касается всех вещей из разных модов, которые связаны
логически» — из логических дублей оставляем **один** предмет с самым сложным крафтом, работающий для всех связанных механик. У остальных
убираем рецепты, JEI, креатив, лут и торговлю; предметы, уже лежащие в мирах, остаются рабочими (из реестра не удаляем). Не трогаем:
боссов и мобов; расы, классы и ядро модов (Origins, Arknights, магию) — только через вопрос владельцу; руды и слитки (их уже сводит Almost Unified).
Энергия — отдельный раздел ниже (вопрос владельца В56 → В63), по ней ничего не меняем до ответа.

Механизм уже есть: список `global.mmDedup` (`pack/kubejs/startup_scripts/dedup_list.js`, «убранный → оставшийся») — рецепты, JEI,
креатив и подстановка в чужие рецепты. Первый пример — один защитный костюм (`docs/compat.md` «Один защитный костюм»).

## Как считали
1. Выгрузка со стенда (`scripts/tests/dedup_dump.js`): 23 318 предметов, 31 246 рецептов (у 2 770 нет предмета на выходе — ритуалы,
   зачарования, жидкости). Теги — статически из jar (`scripts/dedup-audit/tags.py`, 3 403 тега).
2. Сложность крафта (`scripts/dedup-audit/analyze.py`): базовые ресурсы (слитки, самоцветы, пыль, краски, стекло, камень, дерево…) = 1,
   самородок 0,11, блок 9; предмет = 1 (этап) + сумма ингредиентов / выход, по самому дешёвому рецепту. Глубина — число этапов до базовых
   ресурсов, «станки» — некрафтовые типы рецептов в дереве. Ограничение: рецепты, у которых ингредиенты не выгрузились (часть машин
   и sequenced assembly), оцениваются условно (+5); редкость материала (лут, другое измерение) модель не видит — её добавляем руками.
3. Кандидаты (`scripts/dedup-audit/groups.py`): 36 функциональных групп по ключевым словам + одинаковые id у разных модов + одинаковый
   материал и тип брони/инструмента. Затем — ручная проверка, что предметы действительно делают одно и то же.

Повторить: `mkdir -p <сервер>/kubejs/exported`, `EXTRA_SERVER_SCRIPTS=<папка с dedup_dump.js> TEST_COMMANDS=<«#sleep 120»>
scripts/test-server.sh <сервер>`, затем `MM_SERVER=<сервер> MM_AUDIT=<папка с mm_dump_*.json> python3 -I scripts/dedup-audit/{tags,groups,energy}.py`.

## Итог
Проверено **32 группы** (28 функциональных с предметами из ≥2 модов, сетевые хранилища, 3 по материалу брони/инструментов). Из них:
- **очевидные — 3** (делаем пачкой в этапе 2);
- **спорные — 9 вопросов** из 8 групп (нужен ответ владельца, цифры ниже);
- **энергия — 4 группы** (кабели, батареи, генераторы, солнечные панели) — в разделе «Энергия», ждут В63;
- **не дубли — 17** (разная механика, ложное совпадение имени или ядро магии/рас).

## Энергия (для вопроса В63; ничего не меняем до ответа)

Сканирование байткода всех jar сервера (`scripts/dedup-audit/energy.py`):

| Вид энергии | Кто использует | Связь с FE |
|---|---|---|
| **FE (Forge Energy, она же RF)** | Mekanism, AE2 (на входе), Refined Storage, Superb Warfare, Create Crafts & Additions, Create Propulsion, Arknights Endfield, Sophisticated Backpacks (улучшение-батарея), Botania/Ars (связки), Jade (показ) | это и есть общая единица |
| Mekanism Joules (J) | Mekanism, Mekanism Generators, More Machine | внутри J, снаружи FE; **показ уже в FE** (`energyType = "FORGE_ENERGY"` в `config/Mekanism/common.toml`), курс 1 FE = 2,5 J (`feConversionRate`) |
| Botarium (Ad Astra, Giselle Addon) | машины и кабели Ad Astra | на Forge это FE |
| AE2 AE | сеть ME | внутри AE, принимает FE через энергоакцептор (1 AE = 2 FE); показ в AE не настраивается |
| Create SU (вращение) | Create и аддоны: Northstar, Creating Space, Create Nuclear, Big Cannons, Steam 'n' Rails, Propulsion, Occult Engineering, Ars Creo, Mechanical Botania, Valkyrien Skies | **не число энергии**, а механическое вращение (скорость × нагрузка); в FE переводится только машинами Create Crafts & Additions: генератор (SU → FE) и электромотор (FE → SU) |
| Магия: мана Botania, Source Ars, LP Blood Magic, мана M&A и т.п. | магические моды | не трогаем (ядро магии) |

Вывод: в сборке **уже одна универсальная энергия — FE**. Все технические моды, кроме Create, принимают и отдают FE напрямую, Mekanism
и так показывает FE. Отдельно живут только вращение Create (механика, не энергия-число) и внутренний учёт AE2.

Варианты для владельца (простым языком):
- **а) Оставить как есть (рекомендую).** Единица уже одна — FE: провода и батареи любых модов соединяются, Mekanism пишет FE. Вращение Create —
  это «валы и шестерёнки», его переводят в FE и обратно генератор и электромотор Create Crafts & Additions. Работы нет.
- **б) Убрать дубли проводов/батарей/генераторов по правилу «самый сложный».** Энергия от этого не станет «одной» (она уже одна), но
  уменьшится число похожих блоков. Это группы «кабели», «батареи», «генераторы», «солнечные панели» (102 + 26 + 13 + 4 предмета) —
  отдельный разбор по тому же методу, 1–2 PR.
- **в) Перевести Create на FE** — **невозможно** без переписывания Create: вращение — его основная механика.
